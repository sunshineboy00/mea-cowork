## E2E 端到端验收（11-24，真实栈）

**E2E 发现并修复一个真实缺陷（P1 引入）**：`BrowserViewer/index.tsx` 的 painter 创建 effect 用了空依赖数组，而 `<canvas>` 是条件渲染的（连接中/错误态为占位符）——首帧时 `canvasRef.current` 为 null，effect 直接 return，之后**永不重建**，`painterRef` 恒为 null，所有二进制帧被静默丢弃，表现是「帧到达但画面全黑」。修复：改为在 `paintBlobFrame` 内按需懒创建，并记录 painter 绑定的 canvas 元素，元素变化时 dispose+重建；卸载时统一 dispose。修复后 UI 层实测 canvas 544x360、38400 采样点全部不透明、297 种颜色。

**Stage A（服务端 + 真实 Chrome + 真实 WS，无任何 mock）**：
- 初始化链路：`/setup/verify-password` → `/setup/database`(sqlite) → `/setup/initial-admin` → `/auth/login` 全通
- `stream_mode=screencast`，首帧 0.13s；meta 1024x768；seq 单调连续、增量恒为 1（无丢帧）
- 稳态 15.4 FPS @1024x768，1.91KB/帧（注意：此 FPS 受 headless 软件光栅限制，同链路在 756x413 可达 57.8 FPS，非 relay 限流所致）
- 静态页 2.5s → **0 帧**（无变化不出帧，UI 层同样为 0）
- 输入→重绘→回显 13/14 次：median 7.3ms，p90 12.7ms，max 13.9ms（隔离法：hover 变色页，只有真实重绘才出帧）
- cursor 回显：auto ↔ pointer 正确切换，字段名是 `cursor`（不是 value）

**Stage B（真实 Chrome 渲染 dashboard SPA）**：注入 WS 探针在页面自身 socket 上计数 → 44 帧 / 5.7s、1379KB、`stream_mode=screencast`（无 poll 回退），canvas 真实绘制，无页面错误 → **PASS**（连续两轮稳定）。

**环境坑（重要，后续复用）**：
- 应用启动 Chrome **不带 `--no-sandbox`**（macOS 上 `_should_disable_sandbox()` 返回 False），本沙箱沙箱初始化失败 → Chrome FATAL 退出 → CDP 无响应 → 报 `failed to attach browser profile 'user-1': did not receive a valid HTTP response`。解法：服务端加 `BROWSER_USE_NO_SANDBOX=1`。
- `_normalize_nav_url` 会把 `data:` URL 改写成 `https://data:...` 导致导航失败 → E2E 必须用本地 HTTP 页面（`.e2e-pages/` + `python3 -m http.server 9096`）。
- 首次启动服务需 wizard 密码（`$OCTOP_HOME/octop-login.txt`）+ 绑定数据库后 `database_bound` 才为 true；`setup/status` 可判幂等。
- 安全删除锁 `SAFE_DELETE_BULK_GUARD_ERROR state lock timeout` 会全局阻断删除，导致 tempfile 无法探测临时目录 → **pytest 完全无法启动**（`No usable temporary directory found`）；锁释放后自动恢复。同时 Vite `build` 因 emptyOutDir 调 rmSync 失败 → 用 `--outDir .e2e-buildN --emptyOutDir false` 再 `cp` 覆盖到 `src/octop/dashboard/`。
- dashboard 首次进入会有 onboarding 弹窗需关（点「稍后再说」）；远程浏览器页需要点「启动浏览器」才建会话（非自动）。
