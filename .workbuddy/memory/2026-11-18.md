### 关键经验（服务器 vfs 驱动）
- **CentOS 7 内核 3.10 不支持 overlay2，Docker 26 只能用 vfs**：每个层都是完整拷贝，无共享/写时复制。full 版构建需要 ~45G 峰值（18 层 × ~2.4G），100G 磁盘撑不下，**lite 版（~15G 峰值）是唯一可行方案**
- `OCTOP_IMAGE_VARIANT=lite` 会剔除 `src/octop/api/routers/desktop/` 和 `infra/control/desktop/`（dockerignore 的 `--exclude desktop` 模式误伤！rsync 时需显式补传这两个目录），否则 app.py import desktop 报 ImportError
- **vfs 下孤儿层识别**：用 `/var/lib/docker/image/vfs/layerdb/sha256/*/cache-id` + `mounts/*/mount-id` 比对 `vfs/dir/`，不在 registry 里的才是孤儿（曾误判 237 个目录全孤儿，实际 188 个在用）
- 清理孤儿层后**不可立即 docker build 后再 prune**——会把新镜像的层当孤儿删掉，导致镜像损坏（stat vfs/dir/xxx: no such file）；损坏后必须 `docker rmi` 重建
- 构建耗时 ~10 分钟（原生 x86，依赖走腾讯云镜像源 + APT_MIRROR/NPM_REGISTRY/PIP_INDEX_URL 全套 build-arg，缺 APT_MIRROR 时 deb.debian.org 直连超时）
- uv 下载偶发 30s 超时（网络抖动），重跑即可；BuildKit 层缓存会跳过已完成步骤
- 部署脚本沉淀在本地 /tmp/cowork_*.sh（rsync 同步、构建、启动、验证全套 expect 脚本）
- 服务器磁盘基线：61G 已用 / 39G 可用（含新镜像），旧 octop 容器数据卷 octop-data 未动
